## Reuse boundary for the Qwen integer engine

`Qwen3.sol` streams quantized weight rows from chunked contracts, reuses scratch buffers, and implements integer row matmul, residual addition, RoPE lookup, exponential/softmax, and an integer reference convention. Its `matmulRows` dispatches to an int8 kernel that consumes 32 signed weights per word, fully unrolled in groups of eight, or an int16 fallback; each packed row has a shift byte and signed weights, and the accumulated signed Q24 input product is arithmetic-shifted by that row's power-of-two scale. These are useful **engineering patterns**, not a compatible Laya numeric specification by themselves. Qwen's activations are signed Q24, whereas the new LayerNorm spike is signed decimal Q6. Composition needs explicit conversion, quantized weight export, per-operator parity and error budgets. Copying the Qwen kernel also carries its AGPL-3.0-only license and provenance.

Direct reuse is incorrect for Qwen RMSNorm (no mean subtraction), causal KV cache, grouped-query/partial RoPE behavior, SwiGLU, generation and argmax decoder, and Qwen chat tokenization. Laya needs bidirectional full/sliding masks, GELU-gated ModernBERT MLP, the separate ReLU Transformer head, option-marker scoring, and typed decision calibration. A sharded Laya run would also need commitments to token/mask/schema, hidden-state boundaries, layer/segment outputs, weights, and exact integer rules; a Qwen causal resume lineage is insufficient.

## Resource signal, with limits

One width-1024 **external harness call** of the standalone LayerNorm costs about **2.58 million gas** on synthetic input under this repository's optimized `via_ir` Foundry configuration; width 128 costs about **0.324 million**. The Python Decimal synthetic reference differed by at most one Q6 unit at both widths. On a private fixture captured from the first genuine encoder embedding LayerNorm, all **1,024/1,024** outputs exactly matched the independently implemented Q6 integer reference. Versus the captured float32 output rounded to Q6, maximum absolute error was **6 Q6 units (0.000006)** and mean absolute error **1.406 Q6 units (0.000001406)**. That real-row external call used **2,606,297 gas**. The private activation and checkpoint weights are not in the repository. These LayerNorm measurements exclude weight reads, matrix multiplication, attention, the head, and settlement.

`contracts/src/judge/laya/LayaMatmul.sol` reproduces the narrowly bounded Qwen int8/unrolled and int16 row kernels from `solidity-sdk` commit `d44f65d6267cf68edc86c64cff446d1d4fe48d06` under its AGPL-3.0-only license. A private exporter read only the first 32 rows of the selected checkpoint's real `encoder.layers.0.attn.Wqkv.weight` tensor (shape 3072×1024). Its input is the captured genuine LayerNorm output **already rounded to Q6**, then converted to signed Q24. This deliberately approximates the original float32 activation before weight quantization; the float comparison uses that same Q6-rounded input. Each row's actual float weights were rounded to signed int8 or int16 with a nearest-ties-even power-of-two scale. Python separately computed the exact signed accumulation and arithmetic shift.

The int8 scale shifts were 8–10 and int16 shifts 16–18 for these 32 rows. The larger int8 drift is a concrete warning against selecting a weight format by gas alone. This test says nothing about accumulated drift after 28 layers or the final decision margin. The fixture is private; no model weight bytes or raw input appear in the repository.

From the inspected layer shapes, each encoder layer has `4*1024^2 + 3*1024*2624 = 12,255,232` dense linear weights, or **343,146,496** across 28 layers. Token embeddings add **51,576,832** values. The two student head Transformer layers add about **25,165,824** linear weights before scorer/action heads. The earlier alert-student **illustration** at 320 tokens gives about **109.8 billion encoder dense multiply-accumulates** by shape; it is not the selected newsletter run. Instrumentation of the selected two-question float run recorded **123,016,314,880 dense projection MACs**, excluding attention scores and small heads. That is a batch-two workload at padded length 167, not an EVM gas measurement. It is arithmetically equal to **3,754,160 slices of 32,768 MACs**, but actual operator shapes, row scale distributions, calldata versus streamed weights, memory reuse and segment boundaries differ. Multiplying either slice gas number by that count would not establish a network gas budget.

The encoder executes `1 + 27 + 28 + 1 = 57` LayerNorm rows per token: embedding, all but the first attention norm, every MLP norm, and final norm. The selected padded batch has `2*167*57 = 19,038` such rows. Multiplying the standalone real-row external-call gas by that count gives roughly **49.6 billion gas**, but this is **not a lower bound, full-model estimate, or chain gas-budget test**. It repeats ABI/memory costs that a fused implementation might amortize, ignores the expensive dense/attention/weight work, and assumes the current Q6 kernel rather than a proven integrated numeric format. Transaction gas limits, segment size, streaming, reuse and committee execution require their own measured design. A local Foundry call with the repository's enormous test gas limit says nothing by itself about a feasible production transaction.

The next runtime milestone is quantized checkpoint export plus a **whole encoder layer and head reference** with exact integer/EVM comparison on genuine intermediate tensors, followed by measured per-stage gas and bounded segmentation. The current LayerNorm and one 32-row projection are operator-level checkpoints; neither establishes full-model parity, transaction feasibility, or an amortized sharded runtime.
