the move

Stop following rotation. Start accepting it.

rotation-following (the provenance deck)
  • Registry that tracks every key forever
  • DNSSEC oracles, notarized DoH quorums, witnessed Merkle logs, challenge games
  • Standing machinery, standing trust, standing cost
  • Follows rotations — including the ones an attacker makes
rotation-accepting (this deck)
  • One bytes32 pinned at creation + one deadline
  • Settlement proof must match the pin — nothing else exists
  • Deadline passes unresolved → anyone voids → everyone refunded
  • The failure mode is a refund, not a theft

Viable only if keys actually live long enough. So the first half of this deck is measurement: 74 archived keys across nytimes.com, wsj.com, washingtonpost.com, economist.com, gmail.com, irs.gov — cross-checked against live DNS today.

the model in one picture

Four stages, one branch

① pin

Create

Creator fetches the sender's current key — live DoH, two resolvers — and pins keccak(domain·selector·pubkey) into the market terms with a settle-by deadline.

→
② verify & trade

Join

Every client re-checks the pin against live DNS on render. Joining = consent to the pin, like verifying a token address before you LP.

→
③ settle

A zk proof under the pinned key (with t= inside the market window) resolves YES/NO. Nothing else can.

③′ void

Deadline passes unresolved → anyone calls voidMarket(). No proof. No oracle. Absence is the evidence.

→
④ payout

Exit

Settled: winners paid. Voided: everything redeems at par — YES = NO = 0.5, complete sets = 1.0, LPs unwind whole.

why this deletes the oracle problem

Rotation is never proven.
It’s inferred from absence.

We never prove the key died — we observe that nobody could prove it lived. Void-by-timeout needs no DNS oracle, no committee, no challenge game. If the pinned key can still sign, someone settles; if it can’t, the clock settles.

  • The only oracle-shaped moment is creation — and it isn’t a protocol oracle. It’s a market-formation fact each participant checks independently and for free (one DoH lookup).
  • Proving absence is the classically impossible part of every DKIM registry design (no DNSSEC → no authenticated denial). Timeout-void sidesteps it entirely.
  • Two market classes: future-event markets (“will NYT email X before T?”) bear the full rotation hazard — the pinned key must sign a future email. Archival markets (the email already exists) settle immediately and carry ~none.
the surprise upgrade

Pinning buys future-compromise immunity

registry world

Attacker takes the sender’s zone (registrar, NS hijack, ESP tenancy) after markets open. The rotation-following registry does its job faithfully — and imports the attacker’s key. Attacker settles markets with forged mail.

pinned world

The pin was fixed before the compromise. The attacker’s new key ≠ pin, so their forged mail proves nothing. Post-creation DNS compromise achieves nothing at all. Worst case remains: void → refund.

Residual attack surface: theft of the sender’s existing private key (fatal in every DKIM design, not just this one) · poisoning the pin at creation (killed by the archive age-gate — §UX) · a malicious pin vs. traders who never verify (UI auto-verification; and their worst honest outcome is par refund, not loss to a rug).

research IV · what the data almost hid

Three traps the model must respect

trap 1 · a selector is not a key

Records get re-keyed under the same name: zendesk1 held 3 different keys in 2 years, WSJ’s cv-usprod-1 four (~annual). And because these are CNAMEs into the ESP’s zone, one ESP re-key rotates every customer domain at once — zendesk1’s windows are identical on nytimes.com and washingtonpost.com. Pin the key hash (we do), and score hazard per key, never per selector.

trap 2 · archives lag and “lie” about death

economist.com’s whole fleet reads dead-Apr-’26 in the archive; live dig today: all present (the crawler stopped visiting). scph20250409 entered the archive 8 months after birth. So: the pin must come from live DoH — never the archive. The archive’s job is age evidence and hazard stats.

trap 3 · the ESP owns your rotation schedule

NYT’s k2 → dkim2.mcsv.net (Mailchimp) · kl/kl2 → sendgrid.net · zendesk1/2 → zendesk.com · WaPo’s tokens → dkim.amazonses.com (verified live). For CNAME’d selectors the sender can’t even prevent rotation — AWS documents that SES auto-rotates (~90–365d, unannounced). The creation UI must display the CNAME chain: “who owns this pin’s death?”

mechanics · replaces backlog A2’s registry with one bytes32

The whole oracle, in one struct

struct Market {
    bytes32 pinnedKeyHash;   // keccak256(domain · selector · pubkey DER)
    uint64  createdAt;
    uint64  expiry;          // settle-by deadline = the void trigger
}

function settle(Groth16Proof calldata p) external {
    require(block.timestamp <= m.expiry,        "past deadline");
    require(p.publicKeyHash == m.pinnedKeyHash, "not the pinned key");
    require(p.dkimTimestamp >= m.createdAt
         && p.dkimTimestamp <= m.expiry,        "t= outside window");   // SparkPost sets t= (verified)
    require(VERIFIER.verify(p),                 "invalid proof");       // E1 compiled circuit
    _resolve(p.outcome);
}

function voidMarket() external {   // permissionless · no proof · no oracle
    require(block.timestamp > m.expiry && !m.resolved);
    m.mode = Redemption.PAR;       // YES = NO = 0.5 · complete set = 1.0
}

DKIMRegistry, updater keys, grace windows, challenge games — all deleted. The E1 circuit gains one public signal (t=) so pre-market emails can’t settle future-event markets.

economics · rotation risk priced like time value

What a share is worth under void risk

VYES = p·(1−v) + 0.5·v  =  0.5 + (p − 0.5)·(1 − v) p = probability YES · v = market-implied probability of void. Void risk shrinks every price toward 0.5 by the factor (1−v) — the same shape as discounting.
  • Par redemption is clean for the AMM: the pool holds complete sets, so LPs unwind whole; YES+NO always redeems 1.0.
  • Void transfers value from high-conviction winners to losers (a 0.90-YES holder gets 0.50). Acceptable when v is small — which is exactly what the class gates enforce — and it is disclosed, not hidden.
  • Insider wrinkle: someone who knows a rotation is scheduled can buy the cheap side and harvest the void. Profit is bounded by |p−0.5|·stake, and cluster cleanups are foreshadowed on-DNS (the successor key appears first — anyone watching sees the overlap open).
  • Future work: a tradeable VOID outcome (Augur-style invalid share) gives rotation risk its own price instead of compressing YES/NO.
creation & join flow · “the users obviously agree”

Making consent free

1

Live fetch, never archive

Creator’s client resolves the selector via ≥2 DoH resolvers, shows the CNAME chain (“who owns this pin’s death”), computes the pin. The fetched record bytes ride along in creation calldata (~500B) as evidence of what was claimed.

2

Age gate

Pin only keys with ≥ 6 months of archive history. Kills fresh dangling-CNAME poisoning and insert-sign-remove games. A market that skips the gate isn’t invalid — it’s just flagged.

3

Hazard label on the market card

Class A–D chip + duration cap, derived from the measured data. Traders price v with their eyes open.

4

Re-verify on every render

Each client re-checks pin vs live DNS whenever it shows the market; mismatch → red banner. Joining an unverified market is the same trust act as buying an unverified token contract — the UI makes verifying free.

5

Optional: bonded mismatch flag

Anyone can post a bonded onchain “pin ≠ DNS” flag that UIs must surface. Advisory, never adjudicated — traders check DNS themselves.

the trade, stated honestly

What it deletes · what it costs

deleted
  • The DKIMRegistry and its updater committee (backlog A2 → one bytes32)
  • Rotation-following, grace windows, key archival as a trust component
  • DNSSEC / notarized-DoH dependency on the happy path
  • Proving key-absence — the classically impossible part
  • Oracle exposure to post-creation zone compromise
accepted costs
  • Markets are short — class-capped (≤90d on NYT-grade pins)
  • SES-class senders (WaPo) effectively unpinnable
  • Void is real: value transfer toward 0.5, priced by traders
  • Non-verifying traders rely on UI auto-checks against a malicious pin
  • No market survives a benign planned rotation either — the refund is the feature

The witnessed log survives — demoted from trust infrastructure to analytics: it powers the age gate and the hazard ratings, and its absence never blocks settlement.

the honest one-liner

The market doesn’t outlive the key — and that’s the design

It agrees on the key at birth — a fact every participant checks for free. It prices the key’s death like time value. And if the key dies first, it dies gracefully into refunds. No committee ever exists.
